## Executive Summary

The site has gone from a generic SaaS dialer page to something recruiter-specific — that's a genuine improvement. But it's overcorrected. The current copy reads like a **strategy consultancy** writing about recruiter infrastructure. It doesn't sound like Fred on a cold call. It doesn't sound like the proposals. It sounds like a McKinsey deck about recruiter workflow.

The core problem is now **tone and clarity**, not positioning. The positioning is broadly right — recruiter systems, signal-led prospecting, outreach, follow-up. But the language is so abstracted that a recruiter reading it would think "this sounds smart but what do I actually get?"

### The Three Fixes

1. **Strip the consulting language.** Replace "operating layer", "workflow architecture", "category-specific logic" with plain language. Talk like you talk on calls.
2. **Lead with the hook.** The CTA should be: **"Get 5 researched prospects today."** That's concrete, tangible, immediate. Everything else on the site should ladder up to that.
3. **Remove case studies.** Replace with a proof section that uses outcome statements and the ROI guarantee — no named clients, no anonymised stories.

# Part 1: UI & Design Audit

<aside>
🎨

**Overall UI verdict:** The layout and visual hierarchy are decent. The problems are structural and copy-based, not visual. But there are specific UI issues that hurt credibility and conversion.

</aside>

## What's Working (Keep)

- **Dark/minimal colour palette** — professional, not cluttered. Suits premium positioning.
- **Sectioned layout with clear breaks** — the visual rhythm of the page is clean.
- **Service line accordion/expandable structure** — good for keeping the page scannable.
- **Recruiter-only badges at top** ("Recruiter-only focus", "Custom workflow builds", etc.) — good trust signals.
- **Footer is clean** with clear navigation.

## What's Broken (Fix)

### UI Issue 1: No Visual Anchor in the Hero

The hero is text-only with no visual support. No image, no diagram, no illustration, no mock of a dashboard or call queue. It reads like a whitepaper, not a landing page. A recruiter scanning in 3 seconds gets a wall of words.

**Fix:** Add a single visual — either a simplified mockup of a call queue with research displayed (what the prospect would actually see daily) or a clean diagram of the system: Signals → Research → Outreach → Call Queue → Pipeline. Keep it simple and schematic, not a fake SaaS screenshot.

### UI Issue 2: The Meta-Commentary Headers Are Design Notes, Not Copy

These are headers currently live on the site:

- *"Born should read like recruiter infrastructure, not a dressed-up service page."*
- *"The FAQ should remove hesitation, not add more selling."*
- *"The site is strongest when the buyer can self-qualify quickly."*
- *"Case studies should explain what changed operationally."*
- *"The offer is easier to trust when each workflow layer is obvious."*

These are **internal design notes** that somehow ended up as live section headers. They read like comments in a Figma file, not copy a prospect should see. Every one needs to be replaced with a direct, benefit-driven header.

### UI Issue 3: No Founder Section

There's no photo of Fred, no "About" section with a human face. For a high-touch, founder-led agency that takes 3 clients per quarter, the founder is the product. Prospects want to know who they're working with.

**Fix:** Add a section near the bottom — photo, one-paragraph story, direct and personal. Not a corporate bio.

### UI Issue 4: Form / Lead Capture is Missing

The current site has no visible form or lead capture on the page itself. The CTA buttons say "Book a Systems Audit" but it's unclear if they go to a calendar, a form, or an email. There's no embedded form with a qualifying question.

**Fix:** Embed a short form above the footer: Name, Email, Company, "What type of recruiting do you do?" (open text). CTA: **"Get 5 researched prospects today."** Below the button: *"We'll pull 5 real prospects in your niche and walk you through the system on a call."*

### UI Issue 5: Too Many Sections Saying the Same Thing

The page currently has:

1. Hero
2. "What Born controls" section
3. "Why it lands" section
4. "Core system" section (with 3 workflow layers)
5. "Services" section (with 3 service lines, each expandable)
6. Case studies section
7. "Who it is for" section
8. FAQ
9. Final CTA
10. Footer

That's **10 sections** before the footer. Sections 2, 3, 4, and 5 are all describing the same thing in different levels of abstraction. A recruiter reading this would get the same message four times in slightly different consulting language.

**Fix:** Consolidate to 6–7 sections max:

1. Hero + CTA
2. How It Works (the 3-step system, once, clearly)
3. What You Get (deliverables, not workflow theory)
4. Who It's For (quick self-qualification)
5. About / Founder
6. Form + CTA
7. Footer

### UI Issue 6: The Domain Mismatch

The footer says [**hello@born.systems**](mailto:hello@born.systems) but the site is [**born.directory**](http://born.directory). This is confusing. Pick one domain for all touchpoints.

# Part 3: Overall Copy Direction & Tone Guide

## Current Tone Problem

The site now reads like a **B2B strategy consultancy** writing about recruiter operations. Words like "operating layer", "workflow architecture", "category-specific logic", "business effect", "system build" — these are consultant words, not recruiter words.

Compare:

| How the site talks | How Fred talks on calls |
| --- | --- |
| "Signal intake and qualification" | "We find companies that are actively hiring in your niche" |
| "Operating layer instead of tool sprawl" | "One system instead of spreadsheets and inboxes" |
| "A more controlled operating layer that is easier for recruiters to run" | "Your BD runs every day, even when delivery is heavy" |
| "Category-specific logic for recruiter desks" | "Built for how recruiters actually work" |
| "Workflow architecture, CRM structure, task routing" | "Prospecting, outreach, call queue, follow-up — all handled" |
| "Book a Systems Audit" | "Get 5 researched prospects today" |

## Tone Rules for the Rebrand

1. **Write like Fred talks on a cold call.** Direct, no filler, concrete. If a sentence could appear in a McKinsey slide, rewrite it.
2. **Every section should answer "what do I get?"** not "what theory underpins this?" Recruiters are practical. They want to see the daily queue, the research, the follow-up triggers — not an "operating layer."
3. **Name the pain before the solution.** "You're spending full days building lists" before "Born automates prospecting."
4. **Use recruiter language.** "Prospects", "clients", "BD", "pipeline", "desk", "placements" — not "signals", "intake", "workflow layers."
5. **One explanation, once.** Don't describe the same system three times in different levels of abstraction. Trust the reader to get it the first time.

# Part 5: Words & Phrases to Kill

| Kill this | Replace with | Why |
| --- | --- | --- |
| Operating layer | System | Nobody says "operating layer" except consultants |
| Workflow architecture | How the system is set up | Architecture implies complexity and theory |
| Signal intake | Finding prospects / sourcing | Recruiters don't use the word "signal" for BD leads |
| Category-specific logic | Built for recruiters | Logic is abstract; "built for recruiters" is direct |
| Reply routing | What happens when they reply | Routing is a systems term, not a recruiter term |
| Business effect | What changes / what you get | Consultant language |
| Systems audit | Discovery call (with free prospects) | "Audit" sounds like they're being evaluated, not helped |
| Desk | Use sparingly — "firm" or "team" is clearer for the website | "Desk" is insider recruiter jargon — fine on calls, risky on web copy |
| Tool sprawl | Spreadsheets, inboxes, and memory | Name the actual tools they're using, not the abstract concept |
| Memory-driven follow-up | Follow-up that depends on remembering | Plain English beats compound adjectives |
